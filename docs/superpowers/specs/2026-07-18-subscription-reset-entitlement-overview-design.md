# 订阅重置权益总览与赠送明细设计

## 背景

现有“赠送重置”页面可以创建赠送批次并查看批次执行结果，但管理员无法从订阅维度查看当前所有有效订阅实际拥有的重置次数。排查用户权益时，需要在上游订阅、基础周期账本和赠送账本之间手工核对。

用户侧的订阅管理卡片已经返回并展示每笔赠送记录。赠送批次较多时，明细会占用卡片高度，影响额度窗口和重置操作的扫描效率。用户更需要先看到赠送剩余总数，再按需查看每笔赠送的说明、使用情况和到期时间。

## 已确认规则

- 管理员在“赠送重置”页面查看全部有效上游订阅，不只查看仍有可用次数的订阅。
- 管理员按订阅分别查看基础剩余、有效赠送剩余和合计可用次数。
- 合计可用为 `基础剩余 + 有效赠送剩余`。
- 合计为零的有效订阅仍然展示。
- 没有本地基础周期的外部订阅，基础次数记为零，赠送次数正常统计。
- 用户卡片默认只显示赠送剩余汇总，不直接铺开每笔赠送记录。
- 用户通过“查看详情”文字按钮打开赠送明细弹框。
- 弹框展示所有尚未到期的赠送记录，包括已经用完但尚未到期的记录。
- 已过期或已撤销的赠送记录不展示，也不参与汇总。
- 用户订阅卡片最大宽度为 `630px`，移动端仍占满可用宽度。
- 本功能复用现有赠送账本和说明字段，不新增数据库表或迁移。

## 目标

- 为管理员提供完整、权威且可搜索的有效订阅重置权益总览。
- 同时覆盖本地购买订阅和只有赠送权益的外部订阅。
- 让用户卡片保持紧凑，并保留对每笔赠送权益的完整可见性。
- 保持现有额度重置资格、扣减顺序和账本规则不变。

## 非目标

- 不允许管理员在权益总览中直接修改、撤销或补发次数。
- 不改变赠送批次创建流程。
- 不改变基础次数与赠送次数的扣减顺序。
- 不展示已经到期、撤销或不属于当前有效订阅的赠送记录。
- 不为管理员权益总览查询每个订阅的实时额度使用进度。
- 不新增数据库字段、表或数据迁移。

## 总体架构

新增管理员专用的订阅重置权益聚合接口。后端使用管理员 API Key 分页读取 Sub2API 的全部有效订阅，并将每个订阅与本地基础周期、赠送账本关联。接口只读取订阅身份和权益数据，不读取日、周、月额度进度，避免为总览产生逐订阅进度请求。

管理员前端通过该接口渲染“当前订阅权益”表格。用户侧继续使用现有 `GET /api/subscriptions`；现有响应已包含赠送汇总和逐笔明细，只调整卡片与弹框的展示方式。

## 上游客户端

为 Sub2API 客户端新增“分页读取全部有效订阅”的方法，复用现有管理员订阅列表端点和分页响应解析：

- 请求固定使用管理员 API Key。
- 查询条件固定为 `status=active`。
- 按页读取直到权威分页信息确认结束。
- 保留并解析订阅关联的用户与分组信息；缺少显示名称时仍保留相应 ID。
- 无法验证成功响应、分页异常或网络失败均作为权威读取失败返回，不使用部分结果。
- 错误和日志继续遵守现有脱敏规则。

## 管理员聚合 API

新增：

```text
GET /api/admin/subscription-reset-entitlements
```

接口位于现有管理员路由组内，普通用户不能访问。

### 返回项

每个有效上游订阅返回一行：

- `upstream_user_id`
- `username`
- `email`
- `upstream_subscription_id`
- `sub2api_group_id`
- `group_name`
- `starts_at`
- `expires_at`
- `remaining_days`
- `base_reset_limit`
- `base_reset_used`
- `base_reset_remaining`
- `bonus_reset_limit`
- `bonus_reset_used`
- `bonus_reset_remaining`
- `total_reset_remaining`

结果按用户 ID、分组 ID、订阅 ID 稳定排序。

### 基础权益口径

只统计绑定当前订阅且覆盖当前 UTC 时间的 `active` 基础周期：

- 没有当前基础周期时，总数、已用和剩余均为零。
- 剩余为 `max(reset_limit - reset_used, 0)`。
- 未来周期和已经结束的周期不计入当前汇总。

### 赠送权益口径

统计绑定当前订阅、`starts_at <= now < expires_at`，且状态为 `active` 或 `exhausted` 的赠送记录：

- `bonus_reset_limit` 为上述记录的 `reset_limit` 之和。
- `bonus_reset_used` 为上述记录的 `reset_used` 之和。
- `bonus_reset_remaining` 为逐笔 `max(reset_limit - reset_used, 0)` 之和。
- `exhausted` 记录仍参与总数和已用统计，但对剩余贡献为零。
- `expired` 和 `revoked` 记录完全排除。

`total_reset_remaining` 为基础剩余与赠送剩余之和。

### 失败语义

- 上游有效订阅列表读取失败时返回 `502` 和稳定原因 `upstream_unavailable`，不返回部分列表。
- 本地权益查询失败时返回 `500`，不把未知值伪装成零。
- 单项缺少用户名、邮箱或分组名称时仍返回该订阅，前端使用 ID 回退显示。

## 管理员界面

在“赠送重置”页面的创建赠送区域之后、赠送批次历史之前，新增“当前订阅权益”区域。

表格列包括：

- 用户：用户名、邮箱、用户 ID。
- 订阅：分组名称、分组 ID、订阅 ID。
- 到期时间。
- 基础剩余。
- 赠送剩余。
- 合计可用。

交互规则：

- 提供用户关键词搜索，匹配用户名、邮箱和用户 ID。
- 提供订阅分组筛选。
- 提供独立刷新按钮。
- 零次数据使用弱化样式，但不隐藏。
- 默认按后端稳定顺序展示。
- 权益表拥有独立的 `loading` 和错误状态，不阻塞赠送表单、批次历史或延期事件。
- 页面现有 15 秒轮询同时静默刷新权益表。
- 静默刷新失败时保留上一次成功数据并提示“数据可能已过期”；手动刷新可以重试。

首版使用前端搜索和分组筛选，不增加服务端分页。后端仍完整分页读取上游数据，确保管理员看到全部有效订阅。

## 用户订阅卡片

卡片继续展示三个汇总值：

- 基础次数：`base_reset_remaining / base_reset_limit`。
- 活动赠送：`bonus_reset_remaining`。
- 合计可用：`total_reset_remaining`。

卡片不再直接渲染逐笔赠送行。活动赠送区域只显示一个汇总数量；当 `bonus_grants` 非空时，在旁边显示文字按钮“查看详情”。没有尚未到期的赠送记录时不显示按钮。

现有“下次消耗”或“下一基础周期”信息继续保留，额度重置按钮和禁用原因不变。

### 赠送明细弹框

点击“查看详情”后打开当前订阅的赠送明细弹框。每笔记录展示：

- 赠送说明；备注为空时显示“未填写赠送说明”。
- 获赠总数。
- 已使用次数。
- 剩余次数。
- 到期时间。
- 状态：剩余大于零显示“可用”，剩余为零显示“已用完”。

弹框展示现有 `bonus_grants` 中所有尚未到期的 `active` 和 `exhausted` 记录。弹框不暴露内部错误、批次哈希或管理员信息。

订阅数据轮询完成后，若弹框仍打开，则按订阅 ID 更新明细。若对应订阅已经失效并从有效订阅列表消失，则关闭弹框并提示订阅状态已经变化。

### 卡片宽度和响应式

- 卡片使用 `width: 100%` 和 `max-width: 630px`。
- 桌面端网格按可用空间排列多张卡片，单张卡片不会拉伸超过 `630px`。
- 网格行中的卡片继续等高。
- `600px` 以下保持单列，卡片占满容器宽度。
- 无限额卡片继续使用与有限额卡片一致的稳定高度。

## 数据流

### 管理员权益总览

1. 页面加载或轮询触发管理员权益 API。
2. 后端分页读取全部有效上游订阅。
3. 后端批量查询相关基础周期与赠送记录，避免按订阅逐条访问 SQLite。
4. 后端在内存中按订阅 ID 聚合并稳定排序。
5. 前端保存完整结果，并在本地应用关键词与分组筛选。

### 用户赠送详情

1. 用户激活“订阅管理”选项卡时请求现有订阅 API。
2. 卡片读取 `bonus_reset_remaining` 显示赠送汇总。
3. 用户点击“查看详情”时，从对应卡片的 `bonus_grants` 打开弹框，不额外请求接口。
4. 后续轮询按订阅 ID 刷新弹框内的赠送数据。

## 测试策略

### 后端

- Sub2API 客户端正确分页读取全部有效订阅，并固定使用管理员鉴权。
- 多页、空页和无法验证的成功响应处理正确。
- 当前基础周期正确聚合总数、已用和剩余。
- 多笔有效赠送正确聚合；已用完但未到期的记录计入总数和已用、不计入剩余。
- 过期和撤销赠送完全排除。
- 外部订阅基础次数为零，赠送和合计正常。
- 合计为零的有效订阅仍返回。
- 上游失败映射为 `502 upstream_unavailable`。
- 普通用户不能访问管理员接口。

### 前端

- 管理员 API 类型与请求路径正确。
- 权益表展示用户、订阅、基础、赠送和合计数据。
- 用户关键词搜索和分组筛选正确组合。
- 静默刷新失败保留旧数据。
- 用户卡片不再直接渲染逐笔赠送行。
- 存在赠送记录时显示“查看详情”，没有记录时隐藏。
- 弹框展示可用和已用完记录、说明回退、次数和到期时间。
- 轮询后弹框按订阅 ID 更新；订阅消失时关闭。
- 卡片最大宽度为 `630px`，移动端为单列。

### 完整验证

- `cd backend; go test ./...`
- `cd frontend; pnpm test`
- `cd frontend; pnpm build`
- 使用 Playwright 在 `1440x900` 和 `390x844` 视口检查管理员表格、用户卡片和赠送明细弹框，确认无重叠、裁切或异常拉伸。

## 兼容性与发布

- 不需要数据库迁移，现有赠送数据立即可用于汇总和弹框。
- API 只新增管理员端点，现有用户订阅响应保持兼容。
- 前端可与后端同版本发布；后端先发布时不会影响旧前端。
- 发布后重点核对管理员总览订阅数是否与上游有效订阅数一致，并抽查基础、赠送与合计口径。
